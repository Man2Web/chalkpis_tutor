# Live deployment (Coolify on the Hostinger VPS)

The API runs at **https://api.chalkpis.com** (DNS A record `api` -> 200.234.43.196, Let's Encrypt certificate from Coolify).

It is a Coolify **Docker Compose** service named under project "Chalkpis" / environment "production":

- `coolify-compose.json` is the exact compose file (no secrets in it). The API image is built straight from this repository (`context: https://github.com/Man2Web/chalkpis_tutor.git#main:server`), MariaDB 11 runs beside it, and uploads, backups and the database live in named Docker volumes.
- **Passwords are generated by Coolify** (`SERVICE_PASSWORD_DB`, `SERVICE_PASSWORD_ROOT`, `SERVICE_PASSWORD_64_JWT`, `SERVICE_PASSWORD_64_PEPPER`). Nobody typed them anywhere.
- `WA_TEMPLATES` (the five approved template ids) is a plain variable in Coolify's Environment Variables.
- The domain is set in Coolify's **Domains** tab as `https://api.chalkpis.com:8080` (port 8080 is the server's port).

## To update the server

Push to `main` on GitHub, then press **Redeploy** on the service in Coolify (it rebuilds from the repository).

## To switch on WhatsApp login codes (needs the gateway client id and password)

1. In the service's **Edit Compose File** add two lines to the `api` environment list: `WA_CLIENT_ID=${WA_CLIENT_ID}` and `WA_CLIENT_PASSWORD=${WA_CLIENT_PASSWORD}`.
2. In **Environment Variables** type the two values (they are secrets: they live only in Coolify and in your private settings file).
3. **Redeploy**. Until this is done, "send login code" answers 503 (`otp_unavailable`) by design, so nobody can sign in yet.

Do this after the newest code is pushed: the code on GitHub must be the version that treats a blank setting as "not set".
